# Omnidle

A daily pop-culture guessing platform across **Video Games, Anime, Cinema and Music**: four independent daily challenges of ten mini-games each, plus endless free play.

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # typecheck + production build
npm run data:validate  # schema + coverage check for the dataset
```

Stack: Vite · React 18 · TypeScript · Tailwind CSS v4 · Zustand (persisted to `localStorage`) · React Router (hash routing) · canvas-confetti. Deployed to GitHub Pages by `.github/workflows/deploy.yml`.

## Daily mode

Each category has its own challenge at `/daily/<games|anime|cinema|music>[/YYYY-MM-DD]`. `buildDaily(date, domain)` in `src/lib/rounds.ts` seeds a PRNG with a hash of `omnidle:<date>:<domain>`, so every player gets the same ten rounds — ten different mechanics, one each, with no repeated target (Anime and Video Games have eleven mechanics with the voice game, so one sits out each day). Answers don't repeat across days either: each day replays the dailies since `EPOCH` (cached) to know when every work, puzzle and timeline entry last came up, and `leastRecent()` picks among the ones never used, then the ones used longest ago. Specialist dailies do the same. Free Play, Specialist practice and boss fights keep a saved history (`seen` in the store, most recent first) and draw what hasn't come up lately. Works that have real media (cover, item/location image, YouTube clip) are drawn four times as often for the rounds that use them.

Progress is stored per `domain:date` (`src/store/progress.ts`). Each round is a `RoundRecord` (`status`, `guesses`, `score`) and games rebuild their whole view from `guesses`, so half-played rounds resume exactly. Streaks are tracked per category, plus an overall streak (any category completed that day). The archive lists every past day per category since `EPOCH`.

## Mini-games

| Game | Component | Media |
|------|-----------|-------|
| Classic attributes | `ClassicGame` | Green / yellow (partial) / red; shared genres and platforms are ticked, a year within 3 is yellow, ▲▼ for year. Cinema adds Type (live-action / animated), anime adds Creator. Clues unlock after 3, 5 and 7 misses: themes (or, without themes, a side character or track), a credit line, then a side character (albums: a track); any that names the title is skipped |
| Quote | `ClueGame` | Quote with progressive hints; songs reveal written **clues** instead (`facts`: where the song comes from, then its artist) |
| Soundtrack | `ClueGame` + `AudioClip` | Hidden YouTube player, Heardle-style 1→16 s snippets starting ~40% into the clip (or `audio.start`); video revealed at the end. If a clip is missing or won't play, the round becomes a **zoomed-in cover detail** (`ZoomImage`), then text |
| Voice Line | `ClueGame` + `AudioClip` | A character's original voice acting (no openings, endings or soundtrack), 2→16 s snippets from `voice.start`; the speaker is the last hint. Anime clips are in the original Japanese; when none is found, the French dub (marked **VF**, `voice.lang: "fr"`), never an English dub. `node scripts/find-voice-clips.mjs` searches YouTube for anime without a clip (titles only, so picks are worth a listen). Anime and Video Games only |
| Emoji | `ClueGame` | One more emoji per miss |
| Pixelated | `ClueGame` + `PixelCanvas` | Real cover art, de-pixelates per miss; if it won't load, Wikimedia's thumbnail of it, then a scene from the work, then a text clue — never an emoji in place of a picture |
| Timeline | `TimelineGame` | Drag or arrows, 3 attempts |
| Guess from the Image | `ClueGame` + `ObscuredImage` | Picture of an iconic item, partly shown through clear windows (colour-shifted, tilted) that open further with each miss; the description becomes the first hint |
| Location | `ClueGame` + `ZoomImage` | In-world screenshot or real filming/recording location, starting at ×3.2 on a focal point (`location.focus`) and zooming out per miss |
| Cover Puzzle | `TilesGame` + `TilePuzzle` | The cover cut into a 3×3 grid, shuffled, rotated and disguised per tile (colour shift, blur, some inverted or mirrored). Swapping (tap two) and rotating (tap one twice) help read it, but only typing the title wins; a piece keeps its disguise wherever it's moved, and each miss restores two pieces to their true look |
| Connections | `ConnectionsGame` | 16 picture tiles in 4 groups of 4, Yellow→Purple difficulty, 4 mistakes, "One away…" |

`GameHost` adds the shared juice: synthesized WebAudio SFX (`src/lib/sfx.ts`; the 🔊 header button opens a panel to switch them off and set two saved volumes — effects, and clips & voices for the YouTube soundtracks, voice lines and laughs), confetti (`src/lib/fx.ts`), a glow on wins and slide-in round transitions. Finishing a daily plays a fanfare and produces a Wordle-style share text:

```
Omnidle Video Games 2026-10-18 — 820/1000 🔥3
🟩🟩🟨🟥🟩
🟩🟨🟩🟩🟥
```

## Music

Music is **songs**: the title is the only answer — never an album, never an artist. Artists and albums are clues only (the Classic grid's Artist column, the Quote round's clues, credits). The old albums became the song their clip plays, and video game and anime songs joined them (`scripts/data/music-songs.mjs`: openings, endings, boss themes, film themes…), with `node scripts/add-music.mjs` (which also finds their YouTube clips from search results, titles only) and `node scripts/enrich-media.mjs --domain=music --no-youtube` for covers. The music Connections are songs only too.

## Customise

Every game can be narrowed down as an Expedition can (`src/components/Customise.tsx`: a ⚙ Customise panel with every option one by one, All / None per group, remembered on the device). Summit and Crossroads play only the picked franchises; Odd One Out, Six Degrees, Who Am I?, Franchise Wordle, Memory Pairs, Who's That?, Rail Rush and JLPT get a **Your mix** (the picked themes, sets, series, lines, or JLPT levels and kinds, together); Guess the Year mixes kinds of work and decades; Name Them All shows (and draws its random list from) the picked franchises; Higher or Lower's decks of every kind of work keep the kinds picked. A custom run keeps its own best (`…:custom`). Free Play already picks its domain and mini-game; Quick Sort and Map Quiz decks are each one question, so they have nothing to mix.

## Data

- **Works**: `src/data/works/{games,anime,cinema,music}.json`, 100+ per category. Shape: [`schema/work.schema.json`](schema/work.schema.json). Optional fields (`quote`/`tracks`, `audio`, `emoji`, `item`, `location`, `cover`, `visual`) decide which mini-games a work can appear in.
- **Connections**: `src/data/connections.json` (10 per category + 7 mixed) — `domain` decides which daily uses a puzzle (`mixed` = free play), `theme` marks single-universe grids, each group has a `level` 0–3. A tile is a label or `{ "label", "src" }`; `images` sets the puzzle's default picture source (`wp`, `fandom:<wiki>`, `ddragon`). `node scripts/enrich-connections.mjs` resolves them and reports misses — a grid only shows pictures when all 16 tiles have one, since a lone text tile would give its group away.
- **Themed Connections**: `src/data/connection-themes.json` — per theme (One Piece, Zelda, Star Wars...), a list of `cards` and reusable `categories` (`{ id, label, level, items }`). Six grids in ten are built at play time from four of a theme's sub-categories, four tiles each (`settings.json` → `connections.themed`) (`src/lib/connections.ts`, id `theme:<theme>:<seed>`): no tile on a board fits two of its groups (a card listed in several of the board's sub-categories stays off it, so there are never five Fire types for four slots — which needs complete memberships in the data), and boards avoid a lone group of places or objects among characters (`kind` per sub-category, read from the label when left out: "Islands…" is places, "Link's tools" things); when a theme can't avoid one, that group is coloured as the easiest. Sub-categories sharing no card at all in the theme are preferred, and every grid is checked to have exactly one solution. Trio sub-categories (the Legendary Sannin, the Triforce bearers, the Golden Trio) stack extra layers on one franchise. Add a sub-category by listing its cards; `enrich-connections.mjs` fetches the new pictures.

- **Boss Battle**: `src/data/bosses.json` — one guardian per franchise with dialogue, Knowledge Blitz prompts (`"Name|alias|alias"` answers), Radar `members`/`impostors` and Final Blow cards. Cards use the same picture sources as Connections tiles; `node scripts/enrich-bosses.mjs` resolves them. Easy, Medium and Hard (`DIFFICULTIES` in `src/lib/boss.ts`) set the rounds per phase, timers, wave sizes and visual distortion; validation requires pools big enough for Hard (6+ prompts, 12+ members, 10+ impostors, 12+ faces). The numbers live in [`src/data/difficulties.json`](src/data/difficulties.json). `rounds` lists the rounds per phase: Easy plays the first three phases once; Medium and Hard add a fourth, the **Name Chain** (`chain` settings): the boss names something of one category ("Character: Zoro"), the player answers with a different one of the same category, nothing can be named twice, and a wrong category, a repeat or a timeout loses the round (a heart). There are no suggestions and no list of what was already named. Settings: `picksToWin`, `turnSeconds`, `bonus`. Knowledge Blitz answers count only when Enter is pressed. A `secondLoop` block can still make a phase's second round harder, but none uses it now. Emptying the life bar on **Hard** starts the secret **Signature** (`signature` settings: `toWin`, `chances`, `seconds`, `bonus`): one clue on a very specific side of the franchise, no suggestions — a right answer wins; a wrong one or a timeout takes every heart and brings one last chance on a new clue — One Piece laughs (clips), League items by their stats and price (Data Dragon), Genshin constellations, MCU actors, World of Warcraft raids (name the final boss), Overwatch ultimates, Minecraft mob drops, Dragon Ball and Naruto techniques, Star Wars ships, Patronuses, Middle-earth weapons, Final Smashes and Inazuma Eleven hissatsu. Clues live in each boss's `signature` block, written by `node scripts/data/boss-signatures.mjs`. Each boss lists its categories in `bosses.json` (`secret.categories`, entities as `"Name|alias"`) and can override the settings there; `picksToWin` is capped at what the categories allow (floor(n / 2) per category).
- **2D art only in Boss Battle**: 3D models are for silhouettes (Who's That?). `node scripts/data/boss-2d-art.mjs` gives the Overwatch, Smash and Minecraft bosses drawn pictures — Overwatch's "Cute" sprays (Valorant's painted agents as impostors), Smash's fighters in their original series' art or sprites (picked by eye, `scripts/data/boss-2d-art.json`), Minecraft's pixel faces and textures (served from `public/art/minecraft`, as minecraft.wiki blocks other sites) — and marks them `drawnOnly`, so Final Blow takes no card pictures for them (`src/boss/faces.ts`). Faces with no 2D art sit out (`finaleSkip`, `radarSkip`) but keep their cards; every card keeps the picture it was pulled with (`src/data/card-art.json`). Minecraft's pictures are drawn without smoothing (`pixelArt`). For Honor and Destiny have no drawn art on their wikis yet.
- **JLPT boss** (Boss Battle, Other): Oni-Sensei, keeper of the kanji, written by `node scripts/data/jlpt-boss.mjs` from `src/data/jlpt.json`. Its cards are kanji drawn in the browser (`"image": "kanji:山"`, `src/lib/kanji.ts`: ink on squared paper, the guardian a red seal), named by their meaning, with the other meanings and the readings (romaji and kana) as aliases — typed answers keep kana and kanji (`normalizeText`). Every Japanese word, kanji and reading in it comes from the list (no other source). Radar: everyday kanji against N1 ones; Final Blow: N5 and N4 kanji; Knowledge Blitz and Name Chain: the list's words by topic (animals, food, places, the body, colours…), in romaji, kana or kanji; Signature: N3 kanji. The same script writes `src/data/jlpt-cards.json`, so the JLPT card set holds a card for every kanji of the list (2,215 with the boss's, its mythics and its omni, 漢字, which wakes as 合格 ("passed") after a Hard win), each saying its meanings, readings and level; a kanji whose meaning another card already has goes by another of its meanings, else by its meaning and reading ("Kanji (ka)"), so card ids stay unique.
- **French names**: works can carry `nameFr` (the French release title) and boss answers list French spellings as aliases. Both live in `scripts/data/` and are applied by `node scripts/add-french-titles.mjs`. The Inazuma Eleven boss goes further: `node scripts/data/inazuma-french.mjs` makes the French dub names (Mark Evans, Main Magique, Tempête des Gémeaux, Ray Dark…, checked on the French wiki) the displayed names, keeping the Japanese and English ones as accepted answers.
- **Batches of works**: `scripts/data/new-anime.mjs` and `new-games.mjs` hold the latest 100 entries in compact form; `node scripts/add-works.mjs` merges them and gives anime and voiced games a `voice` entry (speaker + search query), then `enrich-media.mjs` fetches pictures.
- **Who's That?** (`/whos-that`): name blacked-out silhouettes one after another until the first mistake — a wrong name or a pass ends the run, and the score is the streak. The results show the silhouette that ended it and what was typed. **Easy** keeps the plain silhouette; **Rising** gets harder every 4 names (turned, then zoomed in on part of it, maybe mirrored, cropped, and finally spinning); **Hell** gives 10 seconds per silhouette (running out ends the run) and cycles one effect per silhouette — normal, turned, zoomed, mirrored, cropped, spinning, then normal again. **Flash** shows the plain silhouette for 1.5 s once its picture has loaded, then hides it; every name shortens the glimpse (geometrically) down to 0.2 s at a 50 streak, where it stays. Crops cut the same slice off two opposite sides and sit outside the turn and spin, so their edges stay straight. Best streaks are kept per mode. Play one series or "All" of a domain. English and French names both count (French names are aliases; names that are the same in French have none). Rosters live in `src/data/silhouettes.json`, built by `node scripts/build-silhouettes.mjs` (League of Legends renders, Minecraft mob renders, Pokémon official artwork with French names, World of Warcraft renders from the Specialist data, One Piece renders from Thousand Storm, with World Seeker, Burning Will and Unlimited World Red as fallbacks — never Bounty Rush, whose glow outline shows as a doubled edge, nor Pirate Warriors, whose renders sit on brush strokes). Only cut-outs with a transparent background work as silhouettes: pictures are checked in the browser (share of transparent pixels, and gaps around the shape) and the choices applied with `--apply=choices.json`.
- **Specialist** (`/specialist`): one universe per page, with a daily (the same rounds for everyone, one of each type, seeded by date, streak and share text) and endless practice. Every universe ends with a **Timeline**: five characters to put in the order they first appeared — debut chapter for One Piece (at least 20 chapters apart), release year for League, debut film for Marvel, release version for Genshin and first game for World of Warcraft (hand-written in `scripts/data/wow-debuts.mjs`); four tries, each showing which places are right, and the debuts revealed at the end (`src/specialist/timeline.ts`, `games/TimelineRound.tsx`). Timeline rounds are left out of the daily no-repeat history, so the days before it was added keep their rounds. One Piece, League of Legends, Marvel (MCU), Genshin Impact and World of Warcraft are all playable. Each universe lists its round types in `UNIVERSES` (`src/specialist/rounds.ts`). One Piece rounds: **Classic** (gender, affiliation, Devil Fruit type, Haki, bounty ▲▼, height ▲▼, origin, first arc ▲▼; close numbers and neighbouring arcs are yellow), **Devil Fruit** (the fruit's picture when it has been shown, opening per miss; hints from its type, name meaning, debut arc, English name and user; naming a character costs a try, and if it's the fruit's user it shows a shortlist of 8 fruits, same type first), **Laugh** (a character's signature laugh in the original Japanese voice, in 1 → 12 s snippets; the written laugh is a late hint, and the clue itself if a clip can't play — clips found by `node scripts/find-laugh-clips.mjs`, titles only, with a reject list for checked mismatches), **Jolly Roger** (the crew's flag) and **Wanted** (the character's wiki portrait on a wanted poster, blurred and in black and white, sharpening with each miss; its colours come back after three misses, as a hint). Data: `src/data/specialist/onepiece.json`, built by `node scripts/build-specialist-onepiece.mjs` from the One Piece wiki — characters from their infoboxes and categories (ranked by subpages and page size, 220 by default; only characters the anime has shown, plus those from chapters it hasn't reached yet), canon Devil Fruits, crews with a Jolly Roger and the wiki's laughter table. Only facts are kept, no article text; re-run it to pick up new characters, bounties and fruits. League rounds: **Classic** (gender, positions, species, resource, range, regions, release year ▲▼), **Ability** (one of the champion's five ability icons, greyscale, turned and blurred, clearing per miss; the ability's key and finally its name as hints), **Splash Art** (a ×3.2 crop of the base splash that pulls back per miss) and **Silhouette**. Data: `src/data/specialist/lol.json`, built by `node scripts/build-specialist-lol.mjs` — champions, abilities, icons and splash arts from Data Dragon; positions, range, resource, class and release date from the League wiki's `Module:ChampionData`; pronouns, species and region from its lore pages. Champions too new for the wiki's data sit out Classic until a later run (`complete: false`). Re-run it after each patch. Marvel rounds: **Classic** on characters (gender, species, team, status, debut film ▲▼, Phase ▲▼, number of films ▲▼), **Film** (a zoomed crop of the poster), **Emoji** (a film told in emojis, hand-written in `scripts/data/mcu-emoji.mjs`) and **Voice Line** (the character speaking in the original English version, 2 → 20 s snippets; clips found by `node scripts/find-marvel-voice-clips.mjs` from YouTube titles, with a reject list for checked mismatches). Data: `src/data/specialist/marvel.json`, built by `node scripts/build-specialist-marvel.mjs` from the MCU wiki — every released film, and the 180 characters with the most films and the biggest articles; pages named after a shared mantle (Captain America, Black Widow…) show the current holder, with the mantle accepted as an answer. Re-run it after each release, and add the new film's emoji line. Genshin rounds: **Classic** (gender, element, weapon, region, rarity, body type, version ▲▼), **Wish Art** (zoomed crop of the wish splash), **Silhouette** and **Constellation** (its name). Data: `src/data/specialist/genshin.json`, built by `node scripts/build-specialist-genshin.mjs` from the Genshin wiki (every playable character but the Traveler); the same data feeds Who's That? Genshin and the Genshin boss (`node scripts/data/genshin-boss.mjs`, then `enrich-bosses.mjs --boss=genshin`). Genshin portraits sit on white: `src/lib/cutout.ts` flood-fills the background away in the browser before they're blacked out. World of Warcraft rounds: **Classic** (gender, race family, faction, class, status), **Art** (a zoomed crop of the character's art), **Silhouette** (a transparent render, blacked out) and **Titles** (their titles, one more per miss; vague ones and ones naming them are left out). Data: `src/data/specialist/wow.json`, built by `node scripts/build-specialist-wow.mjs` from the Warcraft Wiki — only well-known characters from the games: pages Blizzard and the wiki flag as major (Blizzard's *Characters of Warcraft*, Hearthstone heroes, Heroes of the Storm, action figures, faction leaders, city bosses…) ranked by those flags and article size, kept only if they appear in World of Warcraft, with a hand list of iconic ones added (Ner'zhul, Archimonde, the Old Gods…) and of overrated ones left out (Hearthstone originals, minor raid bosses). - **JLPT Specialist** (`/specialist/jlpt`, `src/specialist/jlpt.ts`): the list's kanji and words three ways — **Kanji** (a kanji: give its meaning, or a reading), **Reading** (a word written in kanji: give its reading, in kana or romaji) and **Word** (a meaning: give the word, in kanji, kana or romaji). Data: `src/data/specialist/forhonor-executions.json` (`{ hero, name, youtubeId, seconds }`, 494 executions for 38 heroes), built by `node scripts/build-forhonor-executions.mjs` from every hero's ExecutionsAndEmotes page (the video ids are in the wiki's file metadata).

League of Legends, Valorant, Rocket League and Counter-Strike 2 (competitive skill groups, not Premier or FACEIT). Clips play through `src/components/VideoClip.tsx`: no controls, YouTube's title bar (which names the rank) masked, the frame covered whenever it isn't playing, a mid-game start (25–60 % in, past the loading screen where ranks show); a removed video hands over to the next clip of the same rank. Data: `src/data/ranks.json`, built by `node scripts/find-rank-clips.mjs [--game=lol] [--per-rank=5]` from YouTube search results (no API key) — ladders with emblems (CommunityDragon for League, valorant-api.com, the Rocket League and Counter-Strike wikis) and clips whose **title** names exactly one rank: no montages, compilations, guides or reactions, no "Iron to Radiant" climbs or "2 games off Gold", no smurfs "proving a point" in a low lobby, no other modes (ARAM, TFT, Deathmatch, Premier…), ten minutes at least, at most two clips per channel per rank. ### Scaling the dataset

`npm run data:seed` runs the whole pipeline (optional imports → French names → wiki check → images → clips → Connections and Boss pictures → validation); see the header of `scripts/seed-database.mjs`. Step by step:

```bash
# 1. Import factual metadata (year, genres, studio, creator, characters, tracklist...)
```

`enrich-media` looks up `cover.wiki` / `item.wiki` / `location.wiki` with the MediaWiki API (50 titles per request). Item and location clues can instead carry `src` (`fandom:<wiki>:<Title>`, `wp:<Title>` or a URL), or inherit the work's `fandom` wiki, which is then searched by the clue's `name`. Images whose file name looks like a logo, box art, cover or poster — or equal to the work's cover — are rejected so a clue never shows the title. It also and rejects images when a title redirects to a different subject (e.g. "Hyrule" → the franchise page, whose image would give the answer away). Works without `cover.wiki` get one by search — check those. `--force` re-resolves everything; `--dry` writes nothing.

### Adding cards without changing a day that has started

Adding or changing cards must **never change another game's day that has already started**. The Daily Choice, the Raid Boss and the Daily Card Shop pick cards by the day, and their votes and purchases are stored by card id. If a new card joins the pool mid-day, everyone's questions are drawn again: people who voted can't vote any more, and yesterday's results no longer show (this happened when Genji's Omni was added). So a new card, a rarity change or a new franchise only counts **from the next day**:

```bash
# After adding cards, changing a card's rarity or adding a franchise: record them, from tomorrow by default
npm run cards:ledger
npm run cards:ledger -- --day 2026-12-01
```

It writes `src/data/card-since.json` (the day each new card joined, and a re-graded card's rarity before that day), `scripts/data/card-ids.json` (every card the game had, with its rarity) and, for a new franchise, its `since` day in `src/data/daily-choice.json`. Games read it through `cardOn(card, day)` and `rarityOn(card, day)` in `src/gacha/cardSince.ts`. Any new game that picks cards by the day (the same for everyone, or stored by day) must go through them too. `npm run build`, and so the deploy, stops with a message if a card isn't recorded. Packs, boosters and other random draws aren't affected: a new card can be pulled at once.

Don't reorder or remove existing cards or change their ids either. Their order and ids are what fixes each day's draw, and votes, trades and collections refer to them.

### Card videos

A card's video (a Mythic's or an Omni's: up close with the **▶ Play its video** button, and full screen behind a win) is an MP4 hosted with the site in `public/clips/<set>/`, never a YouTube or TikTok embed: those players show their own buttons (a pause button for ~4 s after any seek, the title, "More videos") and nothing in the page can hide them. GIF-like loops (Tenor, Giphy, Klipy, or ours cropped from one in `public/clips/gif/`) play on their own and need no button; everything else waits for it.

```bash
# One moment of a video: downloaded, black bars cropped, encoded for the card and the full-screen win
node scripts/card-clip.mjs --url=https://youtu.be/BAQvCB3Fnm0 --from=19 --to=41 --out=dbz/goku-ultra-instinct
node scripts/card-clip.mjs --url=... --from=0 --to=5 --out=forts/howitzer --mute    # no sound track
node scripts/card-clip.mjs --url=... --from=0 --to=3 --out=lotr-mythic --gif        # a GIF: clips/gif/, silent loop
```

The settings were chosen side by side on Luffy's Gear 5 (540p at CRF 31 was visibly blocky full screen): **1080p max, H.264 CRF 24 (preset slow), a constant 30 fps, AAC 128 kb/s, `+faststart`** — about 0.3–0.7 MB per second of video. An odd frame rate (Goku's source ran at 29.376 fps) froze the picture in some browsers while the sound went on, hence the constant rate. `cropdetect` mistakes dark scenes for bars: look at a frame before keeping a crop. A re-encoded clip gets a new file name (e.g. `-30fps`), or browsers keep playing the cached old one.

Then, in `src/gacha/cards.ts`: `CLIPS` (the card, or an Omni's awakened form), `FIRST_CLIPS` (an Omni's first form); `clipSound: true` in `STRONG` when the clip's own sound should be heard; a clip that is also the voice line uses the same path as `audio` (heard together). `LIGHT_CLIPS` is for small GIF loops only (they also play in the album grid); a full video there would autoplay. Up close, a video heard once through goes back to the card's picture. The script needs `yt-dlp`, `ffmpeg` and `deno` (`winget install yt-dlp.yt-dlp` brings ffmpeg; `winget install DenoLand.Deno` — without a JavaScript runtime yt-dlp only gets 360p from YouTube).

### Checking in Firefox

Some things only go wrong in Firefox (it paints 3D and animations differently from Chrome). `node scripts/firefox-check.mjs` drives the Firefox installed on the machine (through its WebDriver BiDi remote control, with `puppeteer-core`), headless and in a throwaway profile, against the dev server (`npm run dev`): it can fill the save, open a card up close, play its video and report the frames actually drawn, run any steps you give it, and save screenshots (in the temp folder's `omnidle-firefox/`).

```bash
node scripts/firefox-check.mjs --give=minecraft:omni-steve --card=Steve --play --seconds=5
node scripts/firefox-check.mjs --give=dbz:omni --awake=dbz --card=Goku --play
node scripts/firefox-check.mjs --path=/#/specialist --shot
node scripts/firefox-check.mjs --card=Steve --give=minecraft:omni-steve --steps=my-steps.mjs   # export default async (page, h) => { … }
```

`--headful` opens a real window: Firefox then draws with the graphics card, as on a player's machine — trust only that for animation and video costs (headless, it draws without it and drops frames the real one doesn't). `--chrome` runs the same in the installed Chrome, to tell a Firefox-only fault from a general one (screenshot both, compare). `--reduced-motion` turns on Firefox's "reduce motion" setting, to tell whether an animation is to blame.

What it found so far, in Firefox: no depth sorting of crossing 3D planes (the Omni rings up close are cut in halves, `OmniRingsAround`); nothing lifted (translateZ) drawn inside a size container (the card face, for its cqw sizes) nor past the edges of a hidden-back layer, so the face up close stays flat and its crown and embers stand beside it (`CardLifts`); a `repeating-conic-gradient` of wide rays and thin slivers drew only the slivers (the Celestial rays are written out); and pausing the page's animations during a video only froze what was fading in (removed: in a real window they cost the video no frames). Count a video's frames drawn (`requestVideoFrameCallback`), not its "dropped frames".
